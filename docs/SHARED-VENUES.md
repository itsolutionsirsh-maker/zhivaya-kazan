# Совместные заведения — первый этап

Ветка `dev3/shared-venues`, база `bdb72c7` (main после PR #12, памяти города, газеты и слухов). По поручению Иршата этот пакет расширяет прежний участок dev3: затронуты сеть и Node-сервер. Нужна проверка первого программиста перед слиянием. Подробные интерьеры уже в базе; конфликты четырёх файлов разрешены с сохранением обоих наборов возможностей.

## Поведение

- В одном кафе, баре, магазине, на рынке, в аптеке, библиотеке, музее, театре или гостиничном холле игроки видят друг друга, движение, одежду, имена и облачка речи.
- «Рядом» слышно только в текущем заведении. Городской чат остаётся общим, личные сообщения — адресными.
- Нажатие на персонажа или E рядом с ним открывает личный разговор. Игроки не блокируют друг другу проход.
- На телефоне не больше шести неперекрывающихся подписей ближайших гостей, на компьютере — двенадцати. Остальные персонажи остаются видимыми и доступными для выбора.
- При выходе, смене заведения и разрыве соединения старые персонажи удаляются. После восстановления соединения состав комнаты приходит заново.
- Квартиры, метро и приёмная прокурора не объединяются. NPC, заказы, еда, задания, имущество и денежные операции пока локальные.

## Устройство и совместимость

`venue-room.js` используется и браузером, и сервером. Ключ `v1:<тип>:<x*10>:<y*10>:<хэш названия>` зависит от точки заведения, а не положения игрока у двери и порядка загрузки кварталов. Старый `interior.key` сохранён для расписаний жителей; геометрия публичной комнаты определяется общим ключом.

Presence дополнен `room`, `ix`, `iy`, `ihx`, `ihy`. Наружные `x/y` сохраняются. К старому массиву координат WebSocket добавлены поля комнаты; старый клиент читает прежний префикс. Новый клиент понимает и старый пакет. Общие комнаты требуют обновления клиента и Node-сервера. Проверен HTTP fallback `/api.php` именно Node-сервера; старый PHP-хостинг не входит в приёмку этого протокола.

Сервер держит отдельный индекс участников по комнатам, проверяет допустимый тип/ключ, конечность и границы координат, ограничивает видимый набор через `VIEW_K` (по умолчанию 80). Внутренние гости исключены из наружной сетки толпы. Слова привязаны к комнате, очищаются при переходах, действуют шесть секунд и проходят существующую модерацию, mute/ban и лимит частоты.

Это публичное присутствие с присылаемыми клиентом координатами. Сервер не удостоверяет физическое посещение заведения и не проверяет столкновения с мебелью. На таком присутствии нельзя основывать выдачу денег, платных предметов, штрафов или закрытый доступ. Большое число игроков в одном помещении требует отдельного нагрузочного прогона: ограничение выдаваемых соседей не является обещанием вместимости сервера.

Схема базы и сохранения аккаунтов не меняются. Комнаты существуют в памяти до ухода последнего участника. Откат — вернуть клиент и Node-сервер вместе; миграции базы нет.

## Проверки

```bash
node --test tools/tests/*.test.js
# Windows без запуска дочерних процессов тест-раннера:
node --test --test-isolation=none tools/tests/*.test.js
```

Сетевой прогон требует отдельной локальной базы, не production:

```bash
python3 tools/dev_build.py /tmp/zk-shared
cd server/node && npm ci && cd ../..
GAME_DIR=/tmp/zk-shared DATA_DIR=/tmp/zk-shared-data PORT=8971 node server/node/server.js
# В другом терминале (NODE_PATH нужен тесту, так как ws установлен в server/node):
NODE_PATH=./server/node/node_modules node tools/tests/shared-venues-net.js http://127.0.0.1:8971
```

`shared-venues.test.js`: идентичность комнат, некорректные данные, разделение комнат/улицы/жилья, движение и повороты, выход, очистка индекса, речь и модерация, старые пакеты, лимит соседей, неподвижный отправитель, интерполяция, выбор собеседника и плотные подписи.

`shared-venues-net.js`: 11 сценариев с настоящими WebSocket и HTTP-клиентами на изолированном сервере. Программа отказывается запускаться на внешнем адресе.

В `shots.js` добавлены две сцены для каждого размера: три гостя с репликой и 12 гостей. Итого ожидаются 90 снимков на сборку. В `perf.js` — те же две сцены, всего 15 сценариев. Фикстура одинаковая для main и ветки; на main гости внутри не рисуются.

В окружении Codex: Node-проверки и настоящий сетевой прогон выполнены. Два браузерных клиента встретились в одном кафе, обменялись репликой; после перехода в другое кафе новая реплика не пришла. Снимки сняты через доступный браузер на тех же фикстурах. Мобильная проверка — iframe с CSS viewport 390×844, не физический телефон.

Стандартный `shots.js` остановился на запуске Chromium (`spawn EPERM`); `perf.js` — на ошибке Node/Undici до измерений. Остальные браузерные CLI-наборы здесь не объявляются пройденными. Пробные замеры скрытых страниц до переноса на свежую базу дали лишь 6–9 завершённых кадров за 5 секунд и не годятся для сравнения производительности. После переноса валидных замеров perf также нет. До слияния первый программист должен прогнать все одиннадцать браузерных наборов (включая `citymemory.js`), `shots.js` до/после и `perf.js` ×3 в обычном окружении.
