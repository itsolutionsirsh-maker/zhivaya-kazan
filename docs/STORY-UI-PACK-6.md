## Что сделано

- Чек с фактурой бумаги, позициями и крупным итогом; меню с заметными ценами. Прокручивается содержимое, решения остаются внизу. На 360×640 примерный итог 40 000 ₽ виден сразу.
- Пробуждение на скамейке и в палате: две небольшие встроенные SVG-сцены, плавное раскрытие из темноты и восстановление резкости за 2,6 секунды. Первый текст появляется автоматически, дальше — по нажатию. Ранний тап пропускает ожидание. `prefers-reduced-motion` убирает эффект.
- Для `makeInterior('hospital','Палата','story:ward')`: три койки, тумбочки, капельница, окно, врач у двери. `enterInterior` использует `it.spawn`, игрок появляется на первой койке. Она проходимая, чтобы можно было встать; другие койки остаются препятствиями. Лежачая поза действует только рядом с точкой пробуждения. Обычная больница по-прежнему имеет регистратуру и прежнее оформление.
- `p.story`: яркое пальто и сумочка у `charmer`, чёрная широкая фигура и сложенные руки у `guard`, светлая рубашка, фартук и полотенце у `waiter`. `stranger` рисуется как обычный человек. Детали только на LOD 2; LOD 0 совпадает с прежним рисованием. Персона не мутируется.
- В телефоне `kind:'story'` группируется по `from` в цепочки, сообщения внутри идут по порядку. Статус заявления — отдельная карточка. При одинаковом времени более позднее сообщение имеет приоритет. Сохранение сообщений осталось у `cityPhone.push`.

## Контракт с движком

```js
storyUI.bill({place, items:[{name,price}], total,
  choices:[{t,run,primary:true},{t,run,tone:'alert'}]});
storyUI.menu({place, items:[{name,price}], choices});
storyUI.wake({kind:'bench', lines:['Первая строка','Вторая строка'], onDone});
storyUI.wake({kind:'hospital', lines, onDone});
enterInterior({kind:'hospital', name:'Палата', key:'story:ward'});
cityPhone.push({from:'Алия', text:'Сообщение', kind:'story'});
cityPhone.push({from:'Дежурная часть', text:'Заявление принято', kind:'story-status'});
```

`choices` должен содержать хотя бы одно действие. Экран закрывается **перед** вызовом `run`; можно сразу открыть следующий экран. Каждый обработчик выполняется не больше одного раза. Повторный вызов UI заменяет предыдущий экран без его callback. Escape, Telegram Back и нажатие вне бумаги не обходят выбор. `wake.onDone` вызывается только после последней строки. Возвращаемое значение bill/menu/wake — DOM-элемент, его не следует сохранять в игровое состояние.

Поля исходного задания сохранены. Дополнительно `storyUI.inbox(messages)` строит DOM для телефона; его вызывает `phone.js`. Для статуса рекомендуется `kind:'story-status'`; также распознаются `police-status` и `police`. Это договорённость этого пакета, её нужно использовать в ещё не добавленном движке. Для переписки достаточно `kind:'story'` и одинакового `from`.

Демо: `storyUI.demo('bill'|'menu'|'wake'|'ward')`. Демочеки не списывают деньги; `ward` действительно переводит тестового персонажа в интерьер. Демо предназначены для локальной проверки.

UI не списывает деньги, не регистрирует заявление, не назначает награды и не меняет сохранения. Движок отвечает за эти последствия, запуск/остановку маршрута и момент входа в палату. На время экрана UI ставит `player.busy`, блокирует фон и игровые клавиши, очищает джойстик; при выборе восстанавливает прежние busy/inert/focus перед callback.

## Размер и нагрузка

Новых библиотек, растровых картинок и сетевых запросов нет. Две SVG-сцены встроены строками. Закрытые сюжетные экраны не держат DOM, таймеры или RAF; слушатель клавиатуры сразу выходит, если экран закрыт. DOM удаляется и таймер пробуждения отменяется при завершении/замене. Телефон строит цепочки только при обновлении своего содержимого. Палата использует существующий единственный кэш комнаты; 120 кадров повторно используют тот же canvas. Максимум кэша остаётся 1536×1536.

Разница клиентских файлов: **23 806 байт исходников  8 346 байт gzip**. Это размер передачи, а не измерение оперативной памяти. Полная память устройства не измерялась.

Предварительные замеры до выделения рисования сюжетных персонажей в отдельную ветку, CUA, экран 390×844, CPU ×4, функция `measureCompletedFrames` из проекта:

| Сцена | База FPS | Пакет, первый запуск FPS | Пакет, базовая вкладка остановлена FPS |
|---|---:|---:|---:|
| День, z=5.5 | 52.6 | 41.2 | 59.4 |
| Ночь, z=5.5 | 52.2 | 41.2 | 59.9 |
| Издалека, z=2.5 | 44.6 | 37.2 | 52.5 |
| Детали, z=9.5 | 59.7 | 33.3 | 60.0 |

Разные запуски явно зависят от фоновой работы. При чередовании старого/нового `drawPerson` на одной замороженной сцене (CPU ×1) медианы полного `render()` составили: z=2.5 — 1.908 / 1.867 мс; z=5.5 — 1.933 / 2.183 мс; z=9.5 — 1.892 / 1.833 мс. Обычный масштаб в раннем варианте оказался хуже на 12.9%. Поэтому изменения убраны из общего тела `drawPerson`: обычные люди рисуются прежним кодом, а три сюжетных типажа идут через `drawStoryPerson` и небольшой WeakMap-кэш внешнего вида. Все исходные измерения, включая неудачные, сохранены в `performance.json` архива. Повтор после оптимизации, CPU ×4, одна замороженная сцена, 12 чередующихся серий по 12 `render()` на вариант: z=2.5 — 3.242 / 2.800 мс; z=5.5 — 10.733 / 10.633 мс; z=9.5 — 9.975 / 9.292 мс. В этом контрольном сравнении регрессии нет. Это изолирует изменённую функцию, но не заменяет стабильный полный A/B `perf.js`: общая приёмка по FPS остаётся открытой; ускорение игры не заявляется.
