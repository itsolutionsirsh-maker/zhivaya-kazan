# Районы и группировки: первая версия

База: `83a262e` (после PR #21), ветка `dev3/district-territories`. Это отдельный игровой слой; файлы данных второго программиста не менялись. Имена «Хади Такташ» и «Киноплёнка» — прямое пожелание владельца проекта. Остальные пять названий пока совпадают с районами и меняются в `territory-core.js`.

## Что уже можно пройти

1. Открыть меню → «Районы и группировки». Семь контуров, положение игрока, выбор района, пунктир домашней территории, членство и последняя встреча.
2. Войти в аккаунт и вступить в группировку района, в котором стоишь пешком. Гость остаётся нейтральным. Для просмотра карты сервер не нужен; для членства нужен Node-сервер с `territories:true` в ping.
3. Дома действует множитель силы 1.2. Учебный спарринг с двумя гостями позволяет проверить его без потерь: 84 против 80. Это не гарантированная победа. Повтор тренировки — через 2 минуты; она не откладывает первую встречу на чужой территории.
4. Провести 12 секунд пешком на чужой территории без другого диалога. Двое NPC, размещённых через `sidewalkPos`, предложат разговор. Можно уйти, объясниться мирно (+1 уважения), принять вызов (+2 при победе, −1 при поражении, минимум 0). Деньги и вещи не теряются.
5. Перезагрузить игру в середине разговора и продолжить с сохранённой фазы. Финал остаётся в истории. Следующая встреча — через 10 минут, незавершённая истекает через 5 минут без наказания. Уход и нейтральный статус доступны всегда; новое вступление после выхода — через 30 минут. При выходе уважение обнуляется.

Домашний бонус действует в новых районных встречах. Старые уличные ссоры и PvP он не меняет. Полноценная история вступления между двумя районами — следующий пакет: сейчас вступление сделано явной кнопкой, чтобы сначала проверить основу.

## География

Источник: семь административных отношений OpenStreetMap, официальное API `relation/{id}/full.json`, получено 29.10.2026. Данные © OpenStreetMap contributors, ODbL 1.0. Полные координаты сохранены без упрощения; версия отношения, время его изменения и SHA-256 исходного JSON записаны в `district-bounds.js`.

| Район | OSM relation | Отдельных внешних контуров |
|---|---:|---:|
| Авиастроительный | 2133461 | 2 |
| Вахитовский | 2133462 | 1 |
| Кировский | 2133463 | 1 |
| Московский | 2133464 | 1 |
| Ново-Савиновский | 2133465 | 1 |
| Приволжский | 2133466 | 1 |
| Советский | 2133467 | 3 |

Это точная геометрия указанного снимка OSM, а не юридическое заверение актуальности каждой точки административной границы. Одна группировка на административный район — игровая условность, не историческая карта группировок. Названия и границы этих сущностей независимы.

`tools/fetch_districts.py --cache raw/districts --refresh` обновляет данные из официального API; без `--refresh` воспроизводит экспорт из сохранённых исходных JSON. Экспорт отклоняет разомкнутые, неоднозначные и неожиданные отношения. 3448 вершин, включая замыкающие, используются для определения района и карты. Отдельные участки и отверстия поддерживаются. На точной общей границе выбор детерминирован порядком данных, а встречи запрещены в полосе 20 метров от границы. Вне города результат `null`, ближайший район не подставляется.

Клиент и сервер используют проекцию реально загруженной карты (`lon0/lat0/mlon/mlat`). `engine.js` также переведён с ближайшего административного центра на эти контуры; локальные исторические районы сохраняются только при совпадении родительского района.

## Сервер и интеграция

- Новый модуль `server/node/territories.js`: SQLite-таблица `territories(k,state)` в существующей базе, либо атомарно заменяемый `data/territories.json` для резервного JSON-хранилища. SQLite попадает в существующую резервную копию базы; JSON добавлен в список файлов резервного копирования.
- POST `api.php`, `a:territory`, `token`, секрет текущего присутствия `id`, `op:status|join|leave|start|choice`. Все изменения требуют `rev` и 24–40-значный hex `request`. Повтор последнего запроса возвращает состояние без второго результата. История ограничена восемью встречами, журнал запросов — шестнадцатью.
- Токен проверяется сервером. Вступление и встреча проверяются по свежему сетевому присутствию того же cid/IP. Внутри помещений, в автобусе, в машине и без позиции начать нельзя. Район из тела запроса не считается доказательством местоположения. Выход доступен и без присутствия.
- Членство хранится отдельно от `save/state/prog`; поддельное или старое клиентское сохранение его не меняет. Сброс аккаунта сбрасывает и этот слой. На SQLite это выполняется внутри существующей транзакции сброса кошелька.
- Привязка членства — к аккаунту, не браузеру; смена аккаунта очищает клиентский кэш и NPC. Гостевое членство не создаётся и не переносится автоматически.
- Сила, территория, соперники и случайный исход фиксируются при начале встречи. Случайное число клиенту не отправляется. Для продолжения требуется тот же район и расстояние до начала не более 80 м. Перезагрузка не перебрасывает результат.
- Диапазон сетевых координат расширен с ±5 км до ±45 км: старый обрезал окраины. Новый укладывается в существующую упаковку 10-метровых клеток толпы. У сети по-прежнему клиентское перемещение: это не серверная физика и не защита от телепорта. Поэтому в этой версии нет PvP, денег и передаваемых наград за районные встречи.
- HTML: два листа, кнопка в меню, адаптивные стили; `ui.js` знает закрытие, Escape, фокус и жесты. `net.js` читает серверную возможность. Файлы автоматически входят в текущую сборку `site/js`.

Для будущего сюжета доступны `cityTerritories.open()`, `refresh()`, `snapshot()` (копия), `openMeeting()`. Изменение серверного членства из локального сюжетного файла напрямую не допускается: новый сценарий должен использовать отдельные проверенные сервером переходы.

## Проверки и приёмка

```sh
node --test --test-isolation=none tools/tests/*.test.js
python tools/dev_build.py /tmp/zk-territories
GAME_DIR=/tmp/zk-territories DATA_DIR=/tmp/zk-territory-data PORT=8803 node server/node/server.js
node tools/tests/territories-network.js http://127.0.0.1:8803
node tools/tests/shared-venues-net.js http://127.0.0.1:8803
node tools/tests/territories-browser.js http://127.0.0.1:8803 /tmp/territories-browser
node tools/tests/shots.js /tmp/zk-main 8790 /tmp/shots-before
node tools/tests/shots.js /tmp/zk-territories 8790 /tmp/shots-after
node tools/tests/perf.js /tmp/zk-main /tmp/zk-territories
```

Сетевые и браузерные тесты создают тестовые аккаунты; запускать только с отдельным локальным DATA_DIR. Для сравнения main и ветки запускать новые `shots.js`/`perf.js` на обеих сборках: на main новые сцены показывают прежнее меню и помечаются `supported:false`.

Состояние проверки в этой среде: 238/238 Node, 17/17 новых HTTP-проверок, 11/11 существующих WebSocket/HTTP-проверок. Через встроенный браузер реально пройдены вступление, домашний спарринг, переход в Кировский, разговор, перезагрузка в его середине, мирный финал и история с уважением 1. Проверены 360×640 и 390×844; горизонтального переполнения нет, крестик и кнопки закрытия внутри экрана.

Полные `shots.js`, `territories-browser.js` и `perf.js` требуют отдельного прогона на машине инженера: запуск Chromium/Edge из Playwright здесь возвращает `spawn EPERM`. Ручные снимки приложены отдельно; они не заменяют полный эталонный набор. FPS по `perf.js` не заявлен. До этих проверок пакет считать подготовленным к приёмке, не проверенным для выкладки.
