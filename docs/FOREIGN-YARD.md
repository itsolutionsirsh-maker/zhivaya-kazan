# Чужой двор — глава 1

Ветка `dev3/foreign-yard-story`, поверх свежего main `1a83940` (принятый пакет районов, PR #22). Нужны одновременно новый клиент и Node-сервер; ping объявляет `yardStory:1`. Основу районов см. в `TERRITORIES.md`.

## Как пройти

Меню → «Чужой двор», войти в аккаунт и принять приглашение. Дальше журнал ведёт по семи шагам: приглашение, Тимур, Лейсан, Артур, Руслан, выбор стороны, финал. Встречи доступны и через E возле персонажа. Маршрут использует штатный выбор пешком/автобус/такси/аренда/своя машина; говорить нужно пешком. Нейтральный игрок проходит всю главу. Срока нет, перезагрузка и закрытие окна не отменяют обещания.

Четыре вымышленных персонажа, два реальных административных района. Точки — игровые места встреч на существующей пешеходной сети, без утверждений о реальном проведении турнира. Координаты в исходном kazan.json упакованы в дециметры: тест использует настоящий `buildWorld`, затем проверяет `sidewalkPos` вне зданий. На клиенте позиции кэшируются, чтобы случайная сторона тротуара не менялась каждый тик. При отсутствии загруженной дорожки маршрут ведёт к географической точке; взаимодействие ждёт пешеходную сеть.

1. «Своих не бросил»: поддержать Тимура, вернуться в Вахитовский. Можно явно вступить в «Хади Такташ» или сыграть гостем.
2. «Свои по поступкам»: остаться с Артуром в Кировском. Можно явно вступить в «Киноплёнку» или сыграть гостем.
3. «Общий двор»: вернуться и организовать общую игру независимо. Последняя кнопка прямо предупреждает о выходе из группировки. До неё членство не меняется.

Член другой компании не меняет её скрыто: может завершить главу гостем либо выйти обычным способом и дождаться 30 минут перед вступлением. Ожидание никогда не блокирует гостевой финал. Независимый финал при существующем членстве обнуляет его уважение по обычным правилам выхода; это указано на кнопке и в журнале районов.

## Последствия

Все ранние решения сохраняются. Смешанные составы/составы капитанов меняют финальную реплику Лейсан. Помощь с сеткой/новичком меняет рассказ Руслана при возвращении. Четыре шкалы отношения влияют на формулировки; итоговая сторона определяет, кто готов поручиться.

После финала персонажей можно найти через журнал или встретить у их точек. Первый разговор после турнира сохраняется для каждого персонажа. В районной встрече с NPC появляется «Назвать знакомого с турнира»: после своего финала — в соответствующем районе, после независимого — в обоих. Проверка на сервере, результат `vouched`, без денег и дополнительного уважения, с обычным перерывом между встречами. Это не PvP-защита. Нейтральные игроки по прежним правилам вообще не подвергаются районным встречам; поручительство пригодится, если позже вступить в компанию.

Матч пока описан в финале, отдельной спортивной мини-игры нет. Глава однократная на аккаунт; повторного начисления или стирающего выбор режима переигрывания нет. Новые персонажи — локальные сюжетные NPC; общая сцена турнира между игроками сюда не входит. Автоматические районные патрули не отвлекают до завершения главы, обычные городские события продолжаются.

## Хранение и протокол

`territories.state.story` содержит version, stage, choices, bonds, ending, log (7 переходов), visits (4 человека), серверные timestamps. Старые записи без story читаются как новая глава, миграция клиентских сохранений не нужна. Сброс аккаунта очищает историю. Существующие SQLite/JSON backend и резервные копии покрывают новое поле.

POST `api.php`: `a:territory, op:story, token, id, rev, request, step, choice` (для возвращения `step:visit, person`). Переходы валидируются сервером: текущий шаг, доступный выбор, актуальное уличное присутствие, нужный район и расстояние ≤120 м до географической точки. Клиент открывает выбор в пределах 12 м от точки на тротуаре; E — 5 м от NPC. Клиентский `save` не меняет главу. Повтор request возвращает состояние без второго эффекта, другой payload с тем же request отклоняется, старая rev конфликтует. Незавершённая районная встреча должна закончиться до следующего сюжетного шага. Повторный разговор с уже отмеченным человеком не создаёт новых прогрессов.

Позиция использует существующий клиентский протокол перемещения: это не серверная защита от телепорта. В главе нет денежных или передаваемых наград. Токен/смена аккаунта/запрос в полёте обрабатываются общим клиентом районов; при потере ответа кнопка повторяет тот же request. Старый сервер показывает явное сообщение о неподдерживаемой главе.

## Наблюдение и проверка

Сервер пишет в существующую воронку `foreignyard` только после успешного сохранения: promise, kit, welcome, repair, call, finale, endhome/endaway/endbridge, return. В `mod.html` добавлены подписи. Здесь единица — хэш аккаунта, в старых историях остаётся устройство. Запись воронки best effort; она не блокирует сохранение главы. Финал фиксируется по одному каноническому прохождению, показатель replay не заявлен. Длительность 15–20 минут — цель для проверки с игроками и транспортом, не замер.

```sh
node --test --test-isolation=none tools/tests/*.test.js
python tools/dev_build.py /tmp/zk-yard
GAME_DIR=/tmp/zk-yard DATA_DIR=/tmp/zk-yard-test PORT=8807 node server/node/server.js
node tools/tests/yard-story-network.js http://127.0.0.1:8807
node tools/tests/territories-network.js http://127.0.0.1:8807
node tools/tests/shared-venues-net.js http://127.0.0.1:8807
node tools/tests/yard-story-browser.js http://127.0.0.1:8807 /tmp/yard-browser
node tools/tests/shots.js /tmp/zk-before 8790 /tmp/shots-before
node tools/tests/shots.js /tmp/zk-yard 8790 /tmp/shots-after
node tools/tests/perf.js /tmp/zk-before /tmp/zk-yard
```

Использовать новые shots/perf на обеих сборках. Для старой версии сценарии отмечают `supported:false` и показывают меню. Добавлены приглашение, выбор стороны, финал (9 снимков на трёх ширинах), две perf-сцены. Presentation fixtures подменяют только представление; HTTP-тесты и browser-тест используют настоящий сервер и отдельные тестовые аккаунты. Browser-тест переставляет персонажа к точке как тестовую фикстуру, а все выборы выполняет через UI; он не измеряет качество длинного маршрута.

В этой среде: 257/257 Node, 26/26 HTTP главы, 17/17 HTTP районов, 11/11 существующих сетевых проверок помещений. Ручное прохождение независимой ветки: реальные UI/API, тестовое перемещение между точками, восстановление шага/финала после перезагрузки, возвращение к Руслану. Есть ручные снимки. Автоматические browser/shots/perf не выполнены: запуск браузера возвращает `spawn EPERM`. Перед приёмкой обязательны эти прогоны у инженера и проверка маршрутов на опубликованной карте. FPS и удержание не заявлены.
